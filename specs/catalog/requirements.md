# triptych Catalog Requirements

## Overview

外部ソースから取得してまとめられる最大の作品データを、ユーザーの追跡データとは別の「カタログ」として用意する。アニメと原作（小説・漫画）のつながりを軸に、Web 小説と紙の新刊・近刊までを一つの一覧で引けるようにし、アプリ内で閲覧・検索して、気になったものを自分の Library に追加できるようにする。全件は CSV / JSON でも書き出せる。

レコメンド（ユーザーに合わせたおすすめ）は別機能として後で作るため、このスコープには含めない。カタログは誰が見ても同じ中立なデータとする。

## 実機で確認した取得上限（2026-10-14）

| ソース | 上限・制約 | 取り方 |
|---|---|---|
| AniList | 1つの検索で 5000 件より深く辿れない。上限 30 req/min。`id_greater` は無い | 開始年（必要なら月）で区切って全件。日付の無い作品は人気順の上位で補う |
| なろう | 全 126 万作品。1つの検索条件で取れるのは上位 2500 件（st 最大 2000 + lim 500） | ジャンル別 × 総合評価順の上位（連載作品のみ） |
| カクヨム | API 無し。検索ページは robots で許可、20 件/ページ | ジャンル別の人気順上位（1 req/s） |
| NDL | `ndc` で分類指定ができる（913.6 小説 / 726.1 漫画）。今月以降だけで小説 382・漫画 239 冊 | 過去1年〜発売予定の本を分類別に全件 |
| NDL（JPRO・目録前の近刊、2026-10-15） | OAI-PMH `set=jpro`。登録不要、200 件/ページ、500 件の壁なし。`from` / `until` はレコードの更新日（JST の日）。1日 1,000〜2,600 件だが、2026-09-27 は全件（約 356 万件）が付け直された | 更新日の日ごとに取り、発売日が先月以降の小説・漫画だけ残す。1日 2 万件を超える日は取らない |
| しょぼかる | 全番組（約 8000 タイトル）を1リクエストで取れる。Crawl-delay 60 | 1回で全件 |

## User Stories

### US-201: 取れるだけの作品データを集める
- THE SYSTEM SHALL AniList の日本の全アニメ・漫画・ライトノベル（成人向けを除く）を、題名・形式・状態・期間・話数・巻数・ジャンル・タグ・制作会社・人気・配信サービス・関係（原作・アニメ化・続編など）と一緒に集める
- THE SYSTEM SHALL しょぼいカレンダーの全番組、なろうのジャンル別上位、カクヨムのジャンル別人気上位、NDL の小説・漫画の新刊と近刊を集める
- THE SYSTEM SHALL NDL が目録を作る前の近刊（出版情報登録センター JPRO の登録）も、発売日（日単位）と一緒に集める。目録後の本と同じ ISBN の行（`ndl:<ISBN>`）にまとめ、既存の行の題名・叢書名・細かい日付を壊さない
- THE SYSTEM SHALL JPRO の近刊を、ジャンル語（C コードの対象・形態・内容と JPRO のジャンル）と NDC のリンクで小説・漫画に分け、ムック・絵本・写真集・実用書・成人向けなどは除く
- THE SYSTEM SHALL 各ソースのレート制限と robots.txt を守る（AniList は応答ヘッダーの残数を見て待ち、429 では Retry-After に従う）
- WHEN 収集が途中で止まった時 THE SYSTEM SHALL 次の実行で、取り終えた区切りを飛ばして続きから再開する
- WHEN 収集を再実行した時 THE SYSTEM SHALL 既存の行を最新の値で更新し、重複を作らない
- THE SYSTEM SHALL 日常の更新用に、新しい本・放送中の作品・上位の Web 小説だけを取り直す軽い更新（`build --recent`）を持つ。既存の行は更新するだけで消さず、全件の取り直し（`--fresh`）とは併用できない

### US-202: ソースをまたいで同じ作品にまとめる
- THE SYSTEM SHALL AniList の関係（ADAPTATION / SOURCE / SEQUEL / PREQUEL / PARENT）で、アニメと原作と続編を一つの「作品」にまとめる
- THE SYSTEM SHALL しょぼかる・なろう・カクヨム・NDL の行を、題名の照合で AniList の作品に結び、照合方法と信頼度を記録する
- THE SYSTEM SHALL 信頼度の低い結び付きを作品の統合に使わず、「候補」として表示だけする

### US-203: アプリ内で閲覧・検索する
- THE SYSTEM SHALL 「カタログ」タブで、作品を種別・アニメ化の有無・放送状態・年・シーズンで絞り込み、人気順・新しい順・近日順・題名順で並べる
- WHEN 検索語を入れた時 THE SYSTEM SHALL 題名・別名・読みを、全角半角・大小文字の違いを問わず全文検索する（NFKC・小文字化で畳んだ形も検索用テキストに入れる。2文字以下は検索用テキスト `entries_fts.text` の走査）
- WHEN 作品を開いた時 THE SYSTEM SHALL 原作・漫画・アニメ・Web 小説・紙の本を面ごとに並べ、各ソースへのリンクと結び付きの信頼度を出す
- IF カタログがまだ作られていない THEN THE SYSTEM SHALL 「カタログ未作成」と作り方を表示する

### US-204: 自分の Library に追加する
- WHEN 作品の「Library に追加」を押した時 THE SYSTEM SHALL 選んだ面ごとに Edition を作り、ソースの参照（sourceRef）を付けて Work を作る
- IF 同じ (source, externalId) がすでに Library にある THEN THE SYSTEM SHALL 「登録済み」と表示して二重登録しない
- THE SYSTEM SHALL カタログのデータを、ユーザーが追加した分を除いて端末の IndexedDB に保存しない

### US-205: 書き出す
- THE SYSTEM SHALL カタログ全件を CSV と JSON で書き出せる（CLI でファイルへ、画面からダウンロード）
- THE SYSTEM SHALL 書き出しに作品 ID・ソース・題名・種別・状態・日付・人気・結び付き先を含める

## Non-Functional Requirements

- 規模: 合計 10 万行規模でも、一覧 API は 300ms 以内（ローカル）
- 保存先: `backend/catalog.db`（SQLite・git 対象外）。応答キャッシュ（cache.db）とは別ファイル
- 初回の全件収集はバックグラウンドで 2 時間以内
- 更新は 2 通り。日常は `build --recent`（約 15 分＝JPRO 以外 約 8 分＋JPRO 4〜8 分、＋紐付け約 15 秒）、全件の取り直しは `build --fresh`（月 1 回程度・約 2 時間半）。検索索引（`entries_fts`）の作り方を変えた時は `link`（約 15 秒）を再実行する
- 収集中もアプリと collector は普通に動く（AniList の残数を見て譲る）

## Out of Scope

- レコメンド（別機能）
- AI による要約・タグ付け
- なろうの全件（126 万）・カクヨムの全件の網羅（上位のみ）
- カタログの自動定期更新（手動でコマンドを実行する）
- 目録前の近刊のうち、NDL が一括で更新日を付け直した日（2026-09-27 など）にしか更新の無い登録（次に登録が更新されるか、NDL の目録ができた時に取れる）。書影（NDL のサムネイルは他サイトから 403）
